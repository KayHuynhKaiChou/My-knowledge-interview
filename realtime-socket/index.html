Realtime & Socket

Socket.IO, WebSocket, SSE và WebRTC khác nhau ở đâu, khi nào chọn cái nào; kèm phần reactive stream với RxJS.

1 Socket & Realtime

Socket.IO

  • là một thư viện JavaScript cho ứng dụng web thời gian thực (real-time), cho phép giao tiếp hai chiều giữa client và server thông qua cơ chế event-driven. Nó sử dụng WebSocket làm kênh vận chuyển chủ đạo nhưng có thêm fallback như long polling khi WebSocket không khả dụng
  • Trong Socket.IO, emit là phương thức gửi sự kiện, còn on là cách nhận và xử lý sự kiện đó. Ví dụ emit(“send”, …) thì on(“send”, …) sẽ nhận, cùng “send” name
2 Socket & Realtime

Khác biệt giữa socket.emit() và io.emit()

  • socket.emit(): gửi sự kiện chỉ đến client đang kết nối qua socket (client cụ thể)
  • io.emit(): gửi sự kiện đến tất cả các client đang kết nối tới server
  • socket.broadcast.emit(): để gửi đến tất cả client ngoại trừ chính client phát ra sự kiện

Giả sử có A,B,C trong 1 room, khi A gửi msg

  • socket.emit : chỉ A nhận , B và C thì ko
  • socket.broadcast.emit : B và C nhận, A ko nhận
  • io.emit: A,B,C nhận
3 Socket & Realtime

Namespace

là các "kênh" logic để phân tách giao tiếp giữa nhiều nhóm client – server trên cùng một kết nối vật lý. Giúp tổ chức sự kiện, phân quyền, và quản lý riêng biệt cho từng loại kết nối.

4 Socket & Realtime

Socket

  • Là một điểm cuối (endpoint) trong một kết nối. Để hai máy tính "nói chuyện" với nhau, mỗi máy tính cần phải mở một socket.
  • Một kết nối mạng hoàn chỉnh cần hai socket:
  • Một socket ở máy khách (client) (ví dụ: trình duyệt web của bạn).
  • Một socket ở máy chủ (server) (ví dụ: máy chủ của Google).

HTTP

Là 1 giao thức 1 chiều được dùng để trao đổi dữ liệu giữa client-server dựa trên mô hình request-response

6 Socket & Realtime

WebSocket

là giao thức hỗ trợ giao tiếp hai chiều giữa client và server để tạo một kết nối trao đổi dữ liệu.

Tóm lại:

  • socket đóng vai trò như 1 đường dây của HTTP và Websocket trong việc giao tiếp vì nó là cấp thấp , còn 2 thg HTTP và Websocket là cấp cao hơn
  • 1 chiều tức là client gửi request <=> server phản hồi response và chỉ khi client gửi - thì server mới phản hồi , tức là nếu có dữ liệu mới thì server ko tự động phản hồi về cho client mà client phải request
  • 2 chiều tức là client chỉ request lần đầu và những lần sau server tự phản hồi khi có dữ liệu mới đc cập nhật
7 Socket & Realtime

SSE (Server-Sent Events)

SSE là giao thức cho phép server đẩy dữ liệu liên tục xuống client qua 1 kết nối HTTP giữ mở, nhưng chỉ 1 chiều. Tức là client gửi req đến server, server response cho client rồi lúc sau server vẫn có thể response data mới cho client vì kết nối HTTP vẫn còn mở.

Case study nên dùng SSE:

  • Theo dõi tiến độ 1 tác vụ nền, ví dụ import excel nặng — thay vì polling từ FE để nhận % tiến độ.
  • Live dashboard / theo dõi số liệu real-time.

FE — nhận dữ liệu qua EventSource

const eventSource = new EventSource('/dashboard/stats');

eventSource.onmessage = (event) => {
  const data = JSON.parse(event.data);
  updateDashboard(data); // cập nhật UI ngay khi có data mới
};

eventSource.onerror = () => {
  console.error('SSE connection error');
};

BE NestJS — endpoint SSE bằng decorator @Sse

// dashboard.controller.ts
import { Controller, Sse, MessageEvent } from '@nestjs/common';
import { Observable, interval } from 'rxjs';
import { map } from 'rxjs/operators';

@Controller('dashboard')
export class DashboardController {
  @Sse('stats')
  streamStats(): Observable<MessageEvent> {
    return interval(2000).pipe(
      map(() => ({ data: this.getLatestStats() })),
    );
  }

  private getLatestStats() {
    return { activeUsers: Math.floor(Math.random() * 1000), timestamp: Date.now() };
  }
}
8 Socket & Realtime

HTTP & SSE & Websocket

HTTP — mỗi lần cần dữ liệu phải tự hỏi, hỏi xong đóng luôn

Client ──── hỏi ────► Server
Client ◄─── data ──── Server
       (ĐÓNG kết nối)
Client ──── hỏi lại ────► Server   ← phải TỰ hỏi lại (KẾT NỐI MỚI)
Client ◄─── data mới ──── Server
       (ĐÓNG kết nối)
     ↑
     Server KHÔNG THỂ chủ động báo cho client biết có gì mới —
     chỉ được "nói" đúng lúc client vừa "hỏi".

SSE — chỉ 1 chiều

Client ────(kết nối 1 lần)────► Server
Client ◄─── data 1 ──────────── Server
Client ◄─── data 2 ──────────── Server
Client ◄─── data 3 ──────────── Server
     ↑
     Client KHÔNG THỂ gửi gì ngược lại qua ĐÚNG kết nối SSE này.
     Muốn gửi gì lên server (ví dụ "tôi đã đọc thông báo rồi"),
     PHẢI mở 1 request HTTP HOÀN TOÀN KHÁC (POST /notifications/read),
     tách biệt với kết nối SSE đang chạy.

WebSocket — thực sự 2 chiều, CÙNG 1 kết nối

Client ────(kết nối 1 lần)────► Server
Client ◄─── data 1 ──────────── Server
Client ─── "tôi đã đọc" ───────► Server    ← GỬI NGƯỢC LẠI qua ĐÚNG kênh đó
Client ◄─── data 2 ──────────── Server
Client ─── "gõ tin nhắn..." ───► Server    ← GỬI NGƯỢC LẠI tiếp, vẫn CÙNG 1 kết nối
Client ◄─── data 3 ──────────── Server

WebRTC (Web Real-Time Communication)

là một công nghệ mã nguồn mở cho phép truyền tải âm thanh, video và dữ liệu trực tiếp giữa các trình duyệt web mà không cần cài đặt thêm phần mềm hay plugin trung gian. Công nghệ này giúp kết nối ngang hàng (P2P) nhanh chóng, giảm độ trễ tối đa và được hỗ trợ trên hầu hết các trình duyệt lớn như Chrome, Firefox hay Safari.

12 Angular / RxJS

Reactive state

  • Angular dùng RxJS (thông qua stream)
  • React dùng virtual DOM
  • Vue dùng Proxy

Observable

  • Nguồn dữ liệu có thể phát ra 1 tập hợp nhiều giá trị theo thời gian (giống “dòng dữ liệu stream”) => nó giống như provider.
  • Nó không tự chạy, mà chỉ bắt đầu khi có người “nghe” nó (subscribe).

Observer

  • là một đối tượng sử dụng các giá trị được cung cấp bởi một Observable => nó giống consumer
  • gồm 3 callback chính: next, error, complete

Subcription

  • là 1 obj đại diện cho kết quả của việc gọi .subscribe() trên một Observable.
  • có method .unsubcribe() để hủy việc phát các giá trị của observable (hay là hủy stream)
