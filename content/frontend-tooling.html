1 Phía client

PWA là gì, khác web thường ở chỗ nào?

Đáp án

PWA (Progressive Web App) là ứng dụng web hiện đại được thiết kế để mang lại trải nghiệm gần giống ứng dụng gốc (native app), nhưng vẫn chạy trên trình duyệt — kết hợp tính linh hoạt của web với hiệu suất và khả năng hoạt động offline của app di động.

Những điểm tạo nên một PWA

  • Service Worker — nhờ nó PWA có thể chạy kể cả khi không có internet.
  • Lưu trữ phía client — vì hoạt động offline nên dữ liệu được lưu và query ở IndexedDB / LocalStorage / Cache API.
  • Manifest.json — bản chất vẫn là code web (React, Angular, Vue), nhưng nhờ file manifest mà cài và chạy được trên mobile, desktop như một app.
  • Responsive — khi chạy trên mobile, UI phải responsive để tương thích với màn hình nhỏ.
Trả lời mẫu khi phỏng vấn

"PWA vẫn là web app viết bằng React/Vue bình thường, nhưng bổ sung service worker để cache tài nguyên và dữ liệu nên chạy được offline, cộng thêm manifest.json để người dùng cài lên màn hình chính như app native. Dữ liệu offline em lưu ở IndexedDB hoặc Cache API tuỳ loại. Ưu điểm là không phải build hai app riêng cho iOS/Android, nhược điểm là bị giới hạn quyền truy cập phần cứng so với native."

3 Khái niệm chung

SDK là gì?

SDK — Software Development Kit (bộ công cụ phát triển phần mềm) — là một gói công cụ / thư viện giúp lập trình viên tạo ra ứng dụng nhanh hơn cho một nền tảng, hệ thống hoặc dịch vụ cụ thể (Android, Solana, Firebase…).

Một SDK thường gồm

  • Thư viện — các file .dll, .jar, .js…
  • Tài liệu (docs) hướng dẫn tích hợp
  • Công cụ hỗ trợ (tools): CLI, emulator, debugger…
Phân biệt nhanh với API

API là giao diện để gọi tới một dịch vụ; SDK là bộ đồ nghề đóng gói sẵn (thường bao gồm cả client gọi API đó) để bạn tích hợp nhanh mà không phải tự viết lại tầng giao tiếp.

4 Công cụ phát triển

nx.dev giải quyết vấn đề gì?

Nx là build system và monorepo manager hiện đại cho JavaScript/TypeScript, dùng để quản lý nhiều ứng dụng và thư viện trong một repo lớn (monorepo) một cách tối ưu và hiệu quả.

Cấu trúc repo điển hình

Monorepo với Nx
my-monorepo/
├── apps/
│   ├── web/            # Next.js app (frontend)
│   ├── api/            # NestJS app (backend)
│   └── mobile/         # Expo app (React Native)
├── libs/
│   ├── ui/             # UI components (web & mobile dùng chung)
│   └── utils/          # Logic dùng chung giữa web/api/mobile
├── tools/
├── nx.json
├── package.json
└── tsconfig.base.json
Vì sao chọn monorepo

Code dùng chung (types, validation, UI component) nằm ở libs/ nên không phải publish package nội bộ hay copy code giữa các repo. Nx còn biết app nào phụ thuộc lib nào, nên chỉ build / test lại đúng phần bị ảnh hưởng thay vì chạy lại toàn bộ repo.
