stateful và stateless component

The difference between stateful and stateless is that one has state, and the other doesn’t. That means the stateful components are keeping track of changing data, while stateless components print out what is given to them via props, or they always render the same thing.

Flow render server comp => client comp

cụ thể là quá trình render server comp ở server side và sau đó tiếp tục render client comp ở client side

[Server side]
  • Server Components sẽ được render thành React Server Component Payload (RSC Payload) — một định dạng dữ liệu đặc biệt, hay nó là 1 cây DOM server comp
  • Trong cây DOM server comp, Client Component được thay thế = placeholder , nôn na là tách client comp ra khỏi server comp nhưng có đánh dấu (placeholder)
  • RSC Payload kết hợp với Client Component để tạo HTML sẵn (ở server thì client comp chưa đc render)
  • Gửi HTML tĩnh + RSC Payload + JS bundle của Client component
  • Bên cạnh đó có thể gửi thông qua streaming , tức là HTML tĩnh của comp nào xong trước thì stream trước cho client
[Client side]

React dùng RSC Payload để reconcile cây DOM server component với Client component thông qua chỗ đc đánh dáu (placeholder), nói nôn na là gắn vô lại- React hydrate JS bundle của Client component, đồng nghĩa với việc render client component và gắn sự kiện , …

Concurrent Rendering

  • là một cơ chế mới (giới thiệu từ React 18) để giải quyết các vấn đề về UI như UI block, bị delay khi hiển thị trên UI

  • invalidateQueries: đánh dấu dữ liệu của một query là “lỗi thời” (stale) và sẽ trigger refetch khi query này nằm ở component được mount
  • refetchQueries: trigger refetch ngay lập tức
  • staleTime trong useQuery:
  • default là 0 , tức là cứ mỗi lần mounted lại component dùng query data này sẽ tự động refetch lại query đó
  • giả sử là 5 phút , tức là trong 5 phút query data đc xem là fresh(mới) => ko refetch , còn qua 5 phút thì query data đc xem là stale(cũ) => trigger refetch (khi mount lại component)
  • queryClient.prefetchQuery: đúng với thuật ngữ prefetch tức là chuẩn bị trước rồi sau đó dùng

React hooks

  • là một tính năng được giới thiệu từ phiên bản React 16.8, cho phép bạn sử dụng state và các tính năng khác của React như vòng đời (lifecycle) trong các function component mà không cần phải sử dụng class component.
  • useState: quản lý state (dữ liệu) cục bộ trong 1 function component.
  • useEffect: xử lý side effects như gọi API, thao tác DOM… Bên cạnh đó trả về một "cleanup function" – được dùng để dọn dẹp (cleanup) sau khi component unmount hoặc trước khi effect chạy lại (khi dependency thay đổi).
  • useContext: truy cập dữ liệu global từ React Context.
  • useRef: tham chiếu tới DOM hoặc lưu giữ giá trị mà khi thay đổi giá trị sẽ ko gây re-render component
  • useMemo: lưu giá trị của các thao tác xử lí logic phức tạp, bên cạnh đó có thể lưu lại 1 function component để tránh re-render ko cần thiết
  • useCallback: ghi nhớ hàm để tránh tạo lại trong mỗi lần render

Với useEffect, useMemo, useCallback sẽ có param thứ 2 là 1 array dependency

Redux

  • là một thư viện quản lý trạng thái (state management)
  • Nhiều components => nhiều states . Việc truyền state thông qua props theo cách truyền thống từ cha xuống con sẽ không còn hiệu quả nếu như 2 component cần sử dụng chung 1 state nằm quá xa nhau => gây props drilling
  • Luồng của redux:
  • redux gồm các thành phần:
  • Store: nơi Redux dùng để lưu toàn bộ global state của ứng dụng
  • Dispatch: Khi cần dùng 1 action ở component, ta gọi action đó đơn giản bằng cách sử dụng phương thức dispatch , action nhận 1 params là 1 obj gồm 2 field là type : ENUM và payload
  • Action: định nghĩa các action bằng cách khai báo các tên của hành động trong ứng dụng. Lấy ví dụ ta có 1 state là counter và cần 2 phương thức để tăng và giảm giá trị của counter. Lúc này ta định nghĩa 2 action có tên là 'INCREMENT' và 'DECREMENT' , bên cạnh đó, việc xử lý thay đổi state của counter sẽ nhường cho reducer.

Reducer: hàm xử lý các hành động cụ thể và thay đổi state trong store, gồm 2 params: state, action. Reducer nhận {type, payload} từ action ở param action

Redux Thunk

  • là một Middleware cho phép bạn viết các Action (action thunk) trả về một function (func chứa param là dispatch) thay vì một plain javascript object ({payload, state}) bằng cách trì hoãn việc đưa action đến reducer.
  • Redux Thunk được sử dụng để xử lý các logic bất đồng bộ phức tạp (call API, …)
