18 Câu hỏi ứng dụng thường gặp

Thanh toán đơn hàng qua Stripe Checkout: success URL và webhook khác nhau thế nào?

Đáp án ngắn

BE tạo order pending, tạo Stripe Checkout Session rồi trả URL cho FE redirect. Stripe đưa trình duyệt về success_url; webhook là request server-to-server để BE xác minh thanh toán và cập nhật order. Không xem query string ?result=success là bằng chứng đã trả tiền.

18.1 — Luồng tổng thể

1. FE → POST /orders (gửi sản phẩm/số lượng; không tự quyết định giá)
2. BE kiểm tra giỏ hàng và giá từ DB, tạo order status=pending
3. BE → Stripe API: tạo Checkout Session, gắn success_url, cancel_url và orderId
4. Stripe → BE: trả session.url
5. BE → FE: { orderId, checkoutUrl }
6. FE điều hướng trình duyệt sang checkoutUrl
7. Stripe chuyển trình duyệt về shop.com/orders/123?session_id={CHECKOUT_SESSION_ID}
8. Stripe đồng thời POST event đến api.shop.com/webhooks/stripe
9. BE xác minh chữ ký, xử lý event idempotent và cập nhật order thành paid

Với hosted Checkout, BE tạo Session; FE chỉ điều hướng trình duyệt đến URL Stripe trả về. Secret key chỉ ở BE. Giá và line items phải được tính từ dữ liệu đáng tin cậy phía server, không lấy giá FE gửi lên làm nguồn sự thật.

18.2 — Tạo order và Checkout Session

POST /orders

const order = await db.orders.create({
  userId: auth.userId,
  status: "pending",
  totalAmount: await calculateTotalFromDatabase(cartItems),
  currency: "usd"
});

const session = await stripe.checkout.sessions.create({
  mode: "payment",
  line_items: buildLineItemsFromOrder(order),
  success_url: `https://shop.com/orders/${order.id}?session_id={CHECKOUT_SESSION_ID}`,
  cancel_url: `https://shop.com/orders/${order.id}?result=cancel`,
  client_reference_id: String(order.id),
  metadata: { orderId: String(order.id) }
});

await db.orders.update(order.id, { stripeSessionId: session.id });
return { orderId: order.id, checkoutUrl: session.url };

Lưu stripeSessionId và liên kết Session với order bằng metadata hoặc client_reference_id để webhook tìm đúng đơn.

18.3 — Success URL chỉ phục vụ trình duyệt

Stripe redirect trình duyệt về success_url khi checkout hoàn tất. Trang kết quả có thể hiển thị “Đang xác nhận thanh toán” và gọi API BE đọc trạng thái. Redirect có thể bị đóng tab, lỗi mạng hoặc đến trước khi webhook được xử lý; khách cũng có thể tự gõ URL. Vì thế ?result=success không chứng minh giao dịch thành công.

Có thể thêm {CHECKOUT_SESSION_ID} vào success URL để FE gửi Session ID lên BE. Nếu cần hiển thị tức thì, BE truy vấn Stripe từ server và kiểm tra Session thuộc đúng order; FE không tự đổi trạng thái đơn.

18.4 — Webhook là endpoint do mình sở hữu

POST https://api.shop.com/webhooks/stripe

Stripe gửi event, ví dụ checkout.session.completed
BE:
  1. Đọc raw request body và Stripe-Signature header
  2. Xác minh chữ ký bằng webhook signing secret (whsec_...)
  3. Tìm order qua metadata/client_reference_id, đối chiếu session và số tiền
  4. Trong DB transaction: nếu đơn chưa paid thì cập nhật paid, lưu event/session ID
  5. Trả HTTP 2xx nhanh chóng để Stripe biết đã nhận event

Đăng ký URL HTTPS của BE trong Stripe Dashboard một lần cho mỗi môi trường và chọn event cần nhận. Sau đó Stripe chủ động gọi endpoint khi có event; FE không gọi webhook và không phải cấu hình lại cho từng order.

Xác minh chữ ký cần raw body nguyên bản; middleware parse hoặc biến đổi body trước có thể làm chữ ký không khớp. Signing secret phải được giữ ở BE, riêng theo endpoint/môi trường.

18.5 — Retry, event trùng và trạng thái

  • Stripe có thể retry webhook khi BE lỗi hoặc timeout; lưu event.id với unique constraint và cập nhật order idempotent.
  • Event có thể đến không đúng thứ tự. Chỉ chuyển trạng thái theo quy tắc hợp lệ, không để event cũ đổi paid về pending.
  • checkout.session.completed báo Checkout hoàn tất. Với phương thức thanh toán bất đồng bộ, xét event thành công tương ứng như checkout.session.async_payment_succeeded trước khi giao hàng.
  • Nếu tạo order xong nhưng gọi Stripe lỗi, giữ trạng thái chờ/khởi tạo lỗi để retry hoặc xử lý theo chính sách. Dùng idempotency key để retry không sinh thêm giao dịch ngoài ý muốn.
