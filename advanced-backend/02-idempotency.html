Advanced Backend / Câu 02
2 Câu hỏi ứng dụng thường gặp

"User bấm nút thanh toán 2 lần do mạng chậm — tránh trừ tiền 2 lần thế nào?"

Đáp án

Dùng Idempotency Key: client generate 1 UUID duy nhất cho mỗi thao tác, gửi kèm header. Server lưu key này kèm kết quả xử lý; nếu key đã tồn tại và đã hoàn tất, trả lại y nguyên kết quả cũ thay vì xử lý lại.

1. Client gửi request kèm header: Idempotency-Key: uuid-v4
2. Server check bảng idempotency_keys WHERE key = X
   - Nếu có & status = completed → trả lại response đã lưu, KHÔNG xử lý lại
   - Nếu chưa có → INSERT key với status = processing (cột key có UNIQUE constraint)
3. Xử lý giao dịch thật
4. Update record: status = completed + lưu response

2 request cùng key đến gần như đồng thời thì sao?

Dựa vào UNIQUE constraint trên cột idempotency_key ở DB. Request đến sau sẽ bị lỗi duplicate-key khi INSERT → catch exception, chờ hoặc trả kết quả của request đầu (hoặc 409 bảo client thử lại).

Idempotency key nên lưu bao lâu?

Thường 24 giờ — đủ để cover retry do mạng chậm/timeout client, không giữ mãi gây phình dữ liệu. Hết hạn thì cho phép request với key đó chạy như request mới.
